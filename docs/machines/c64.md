# Commodore 64 source machine (design only, not implemented)

The transcoder (`kit/xc65.py`) is machine-independent: 6510 = 6502, and the C64 needs no new opcodes. What changes is the hardware layer: the host model, the survey tables, the runtime services and the video converter. This document is the plan for a first C64 port. Nothing here is tested.

## What has to become pluggable

| part | Apple II now | C64 needs |
|---|---|---|
| host model (`kit/host/`) | `apple2.py` + Disk II | A C64 model with VIC-II registers, CIA timers/IRQ, SID writes, `$01` banking, a 1541 (or KERNAL LOAD hooked at the file level), and a raster-line clock (63 cycles × 312 lines PAL / 65 × 263 NTSC) |
| profiler EA classes | zp/stack/ram/hires/io/rom | screen RAM, bitmap, sprite pointers, colour RAM `$D800`, VIC `$D000-$D02E`, SID `$D400`, CIA `$DC00`/`$DD00`, KERNAL/BASIC ROM |
| survey (`kit/survey.py`) | `SOFTSW`, `ROM_KNOWN` tables | the same tables for C64 registers and KERNAL entries (`$FFD2` CHROUT, `$FFE4` GETIN, `$FFD5` LOAD, `$FFBA`/`$FFBD` SETLFS/SETNAM, `$EA31` IRQ) |
| translated I/O | `$C0xx` handlers | `$D000-$DFFF` handlers. Most VIC/SID writes are plain register stores into a shadow the runtime reads; reads of `$D012` (raster), `$D01E`/`$D01F` (collisions) and CIA timers need real values. |
| memory map | Apple RAM 1:1 at `$0000-$BFFF` | C64 RAM is 64K. `$0000-$BFFF` maps 1:1, but `$C000-$FFFF` collides with the CoCo runtime and I/O. Games that use RAM under I/O/KERNAL (common) need relocation of those blocks in the transcoder's address mapping (a per-access remap for `$D000-$FFFF` data, rare in code). |

## Runtime services to write (`rt/natives/c64/`)
- **Video, bitmap mode** (320×200 hires or 160×200 multicolour, 8×8 cells with colour from screen RAM / `$D800`). Convert per cell into GIME 320×200×16 (the GIME can do 320×200 at 16 colours). The dirty unit is a cell (8 bytes + 2 colour sources), and the conversion is table-driven per byte with a per-cell palette pair. Unlike the Apple there are no artifact colours, so it is simpler.
- **Video, character mode:** a dirty-cell list; draw the glyph from the charset into the GIME buffer. Custom charsets are RAM: watch writes to them (a charset change dirties every cell using it).
- **Sprites (8 hardware sprites, 24×21, multicolour, X/Y expand, priority):** the CoCo has none. Draw software sprites with save-under into the GIME buffer after the background conversion, at the positions in the VIC shadow at frame time. Collision registers (`$D01E`/`$D01F`), if the game reads them, need software collision on the sprite masks. This is the costliest part; budget it first.
- **Fine scroll** (`$D016`/`$D011` low bits) plus the coarse scroll the game does by copying screen RAM. Combine the GIME horizontal offset (`$FF9F`, 2-pixel steps in 320 mode) with row-start changes; otherwise reconvert.
- **Raster splits** (IRQ at a line changes registers mid-screen: status bars, multiplexed sprites): emulate with GIME horizontal-border timer IRQs (`$FF94`/`$FF95` timer + `$FF92`/`$FF93`) at the same lines, or flatten them (apply the per-band register values while drawing that band).
- **SID → DAC:** 3 voices with ADSR. Options: (a) a 2-3 voice square/pulse mixer at a fixed sample rate in the FIRQ (costly; 8 kHz ≈ 15% CPU); (b) the main voice only; (c) pre-rendered effects. Read the game's music player: transcoding the player and synthesizing only its register writes is the usual design.
- **Keyboard:** CIA `$DC00`/`$DC01` matrix scan. Translate to a C64 matrix image built from the CoCo matrix in the IRQ, so the game's own scan routine works unchanged.
- **Joystick:** port 2 at `$DC00` (bits 0-4) from the CoCo right stick (digital thresholds) and its button.
- **Disk:** KERNAL LOAD / fastloaders → snapshots + a native level loader (same as Apple: the `.d64` loader code is not translated).
- **Timing:** C64 PAL 0.985 MHz (NTSC 1.023). Pace frames with the 50/60 Hz GIME VSYNC; cycle-timed code becomes native, as on the Apple.

## First C64 port: suggested order
1. Host model with KERNAL LOAD hooked at the file level (no 1541 emulation), enough to snapshot.
2. Survey tables for C64.
3. A character-mode game without sprites, to prove the cell converter.
4. Then software sprites, then raster splits.
